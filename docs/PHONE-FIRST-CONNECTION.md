# 手机传感器：首次离线连接

此流程使用 Windows 自己提供的局域网网页和配对服务，手机与电脑都不需要访问互联网。先把两台设备连接到允许彼此访问的同一 Wi-Fi / 局域网；无外网的路由器也可使用。学校访客网络的客户端隔离可能阻止设备直连。

当前实现是 P0 验证版：同时连接一部手机、绑定一个实验输入。界面和协议的软件检查不等于 Android、iPhone 或 Windows 的实机验收。

## 第一次使用这台电脑

1. 在 Windows 设置中打开「手机传感器」，选择手机能够访问的局域网地址，启用离线服务。
2. 手机系统相机扫描配对二维码，在 Safari / Chrome 打开电脑提供的本地 HTTPS 页面。
3. 若浏览器显示证书提示，先核对地址是否为电脑显示的 IP 和端口；浏览器提供继续访问选项时，可明确选择继续。不同手机是否提供该选项，以及继续后是否允许实际采集，仍需实测，不能保证全部机型通用。
4. 在页面点击「连接 Windows」，电脑出现接入请求后确认这部手机。
5. 连接完成后，分别点击需要的运动传感器、麦克风或摄像头授权按钮。Windows 只会列出已经取得真实数据的能力；授权不代表该浏览器一定提供对应数据。
6. 在 Windows 绑定实验输入，再开始实验。手机页面保持前台；切换应用、隐藏页面或锁屏会停止采集并释放设备。

默认流程只使用浏览器，不要求安装应用或进入手机系统安装证书。若浏览器不允许继续，或继续后仍阻止采集，应记录实际错误；下方手动信任证书仅为可选兼容办法，不是首次扫码前置步骤。当前 Android / iPhone 路线尚未完成实机验收。

## 不配对也能检查传感器

在当前 HTTP 引导端口和 HTTPS 采集端口，均可打开 `/sensor-check.html`。使用软件显示的当前 IP 和端口，不猜测固定端口。这个独立页面不需要配对码、不连接实验、不向电脑上传采集数据。

先比较 HTTP 与 HTTPS 页显示的 `isSecureContext` 和接口是否存在，再点击各个授权按钮。**接口存在、权限获准、取得真实数据是三件不同的事。** 麦克风应有真实采样，摄像头应出现实际预览，运动传感器应收到含有效分量的事件；只看到 API 或获准提示不能算成功。停止按钮释放传感器。HTTP 页面主要用于对照浏览器限制，不能预期它能调用受限接口。

浏览器源码为这条验证路线提供依据：[WebKit 已移除 getUserMedia 的证书专项检查](https://bugs.webkit.org/show_bug.cgi?id=205493)，目前的[安全上下文判断](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/dom/Document.cpp)根据来源和祖先来源判断；Chromium 的[权限来源检查](https://github.com/chromium/chromium/blob/main/components/permissions/permission_context_base.cc)同样使用来源可信性判断。这些证据不替代已发布手机浏览器的实机结果。

## 可选：手动信任本机证书

只有需要兼容处理时才打开首次连接/证书设置二维码。HTTP 引导页提供公开 CA 证书和说明；安装前核对 Windows 设置显示的完整 SHA-256 指纹。不要将 CA 私钥或 PFX 文件复制到手机。

同一 CA 通常只需配置一次。若电脑重新生成 CA、证书过期或更换设备，应重新核对；若局域网地址变化，先由 Windows 更新离线服务和二维码。安装过程可能超过配对码有效期，完成后生成新配对码。

### iPhone / iPad（可选证书信任）

在 Safari 下载电脑提供的证书后，按系统提示到「设置 → 通用 → VPN 与设备管理」安装对应的证书描述文件。随后到「设置 → 通用 → 关于本机 → 证书信任设置」，为核对过的这台电脑 CA 启用完全信任。

手动安装证书并不会自动获得 SSL 信任，第二步不能省略。菜单名称可能随系统语言或版本略有变化；参见 [Apple 的手动证书信任说明](https://support.apple.com/en-nz/102390)。受学校或企业管理的设备可能需要管理员允许安装证书。

完成后使用 Safari 扫描新的配对二维码，并在运动传感器授权提示中选择允许。不要在微信等应用内置浏览器中进行首轮验收。

### Android（可选证书信任）

下载电脑提供的 CA 证书，在系统设置中查找「安装证书」或「加密与凭据」，选择 CA 证书并选中下载的文件。Pixel 的入口通常在「安全和隐私 → 更多安全设置 → 加密与凭据」。设备可能要求输入锁屏密码；不同厂商的菜单位置有所不同。

安装后回到 Chrome 打开新的配对二维码。证书的安装与移除方法见 [Google Pixel 的证书管理说明](https://support.google.com/pixelphone/answer/2844832?hl=en)。系统可能显示用户 CA 信任提示；应核对证书确实来自这台 Windows 电脑。

## 连接和采集问题

| 现象 | 检查方法 |
| --- | --- |
| 引导页无法打开 | 检查两台设备是否在同一网络、Windows 是否选择正确网卡、离线服务是否仍开启；检查防火墙对这台应用的局域网访问许可。 |
| HTTPS 提示证书错误 | 核对电脑 IP/端口；浏览器允许继续时验证实际采集。无法继续或采集被阻止时记录错误，再考虑可选证书信任；同时检查日期和当前地址。 |
| 页面提示等待 Windows 确认 | 回到电脑确认接入请求。超时后重新生成配对二维码。 |
| 已配对但直连失败 | 检查 Wi-Fi 客户端隔离、防火墙或 VPN；当前实现不通过互联网中继。 |
| 找不到运动传感器 | 使用系统浏览器并主动授权；等待真实数据。部分设备或浏览器不提供角速度或线性加速度，不能用模拟数据补齐。 |
| 麦克风/摄像头没有权限提示 | 检查 HTTPS 页的安全上下文、接口状态和浏览器网站权限；关闭占用设备的应用后重新启用。 |
| 页面提示处理过慢或未确认数据 | 本次采集已停止，避免静默缺样。减少启用的传感器，确保电脑实验页面在前台，然后重新连接。 |
| 图像跳帧 | P0 限制为 320 × 240、最高 5 帧/秒；等待上帧确认或图像编码过大时会跳过，并显示计数。 |

未开始实验时，绑定输入可能发送真实就绪探测；这些探测用于确认连接可用，不记录为实验测量。开始实验后会切换到新的测量序列。

## 结束使用

点击手机「停止并释放传感器」或在 Windows 解除绑定。结束本次功能验证后可以在 Windows 停用离线服务。若曾手动安装证书，且不再信任或不再使用这台电脑，可在手机设置中删除它的 CA/证书描述文件；不要批量移除其他应用或学校网络所需的证书。

实机验收至少覆盖：断开互联网后首次设置与重新配对、浏览器证书提示及继续后的结果、各项真实传感器数据进入对应实验、暂停/重启、后台停止、断网清理。当前软件自动化不能代替这些验收记录。
